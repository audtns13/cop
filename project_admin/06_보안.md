## 인증 & 세션

| 항목 | 설정값 | 설명 |
|------|--------|------|
| 인증 방식 | JWT + httpOnly Cookie | JS에서 토큰 직접 접근 불가 |
| 세션 유지 시간 | **30분** | 마지막 로그인 기준, 갱신 없음 |
| Cookie 속성 | `httpOnly: true` | XSS 공격으로 토큰 탈취 불가 |
| Cookie 속성 | `secure: true` (운영) | HTTPS에서만 전송 |
| Cookie 속성 | `sameSite: lax` | CSRF 기본 방어 |
| JWT 비밀키 | 환경변수 `JWT_SECRET` | 코드에 하드코딩 금지 |

## 권한 구성

### 사용자 역할 (user_role)

| 역할 | 값 | 접근 가능한 기능 |
|------|----|----------------|
| 관리자 | `ADMIN` | 전체 기능 + 회원 승인·삭제·비밀번호 초기화·모든 게시글 수정/삭제 |
| 일반 회원 | `USER` | 본인 게시글 작성·수정·삭제, 출결 등록, 투표 |
| 미승인 회원 | (PENDING) | 로그인 불가 — 어떤 기능도 사용 불가 |

### 회원 상태 (status)

| 상태값 | 의미 | 로그인 |
|--------|------|--------|
| `PENDING` | 가입 신청 완료, 관리자 승인 대기 | 불가 (403 반환) |
| `ACTIVE` | 승인 완료, 정상 회원 | 가능 |
| `NULL` | 상태 컬럼 추가 전 생성된 구계정 | ACTIVE 동일 취급 |

### 초기 관리자 계정

| 항목 | 값 |
|------|----|
| 사번 | `EMP001` |
| 초기 비밀번호 | `1234` |

> ⚠️ 서비스 오픈 전 반드시 비밀번호 변경 필수

## API 보안

### 인증 검사 흐름
```
요청 수신
  → Cookie에서 JWT 파싱 (lib/auth.js - getUser)
  → JWT 서명 검증 + 만료 시간 확인
  → 실패 시 → null 반환 → 401 응답
  → 성공 시 → user 객체 반환 → 처리 계속
```

### ADMIN 전용 API 보호 예시
```javascript
const u = getUser(req);
if (!u) return res.status(401).json({ error: '로그인 필요' });
if (u.userRole !== 'ADMIN') return res.status(403).json({ error: '권한 없음' });
```

### SQL Injection 방지
```javascript
// 반드시 파라미터 바인딩 사용
pool.query('SELECT * FROM tb_user WHERE user_id = $1', [userId]);

// 문자열 직접 조합 금지
// pool.query(`SELECT * FROM tb_user WHERE user_id = '${userId}'`);  ← 위험
```

## AI 챗봇 보안

| 항목 | 처리 방법 |
|------|-----------|
| API 키 노출 방지 | `GEMINI_API_KEY`는 `api/chat.js` 서버사이드에서만 사용, 프론트엔드 미노출 |
| 인증 | `getUser(req)` — 로그인 없으면 401 반환 |
| Prompt Injection | 시스템 프롬프트 분리, 사용자 입력은 `user` role로만 전달 |
| 출결 등록 권한 | `register_attendance` 내 `userId`는 JWT에서 추출 (사용자 입력 불가) |
| 요청 한도 초과 | Gemini 429 응답 시 사용자에게 안내 메시지 표시 |

## 파일 업로드 보안

| 항목 | 내용 |
|------|------|
| 저장 방식 | DB의 `file_data TEXT` 컬럼에 Base64 저장 |
| 실행 파일 차단 | 서버 측 실행 없음 (DB에만 저장, 직접 실행 불가) |
| 다운로드 | JS Blob URL 방식 (서버 파일 직접 노출 없음) |
| 용량 제한 | 서버 측 명시적 제한 없음 → 운영 정책으로 파일 크기 안내 필요 |
